# 今日事项

一个原生 macOS 应用和 WidgetKit 桌面小组件，从 Excel 日程表读取当天事项。所有项目文件都保存在本文件夹。

当前版本：**1.3（构建 4）**。使用 SwiftUI、WidgetKit 和 App Intents 构建，支持 macOS 14 及以上版本，无第三方库依赖。

## 开始使用

1. 安装完整 Xcode，并打开 `TodaySchedule.xcodeproj`。
2. 按下文“通过 Xcode 运行原生小组件”配置自己的签名与 App Group，然后运行应用。
3. 首次运行没有预设文件。点击“选择 Excel…”选择自己的 `.xlsx` 日程表，并设置起始年月。

左侧显示今日卡片，右侧可查看指定日期的全部事项。点击圆圈标记完成；再次点击取消。完成状态先保存在本机；启用 Excel 写回后，会自动给对应事项添加或撤销删除线。

应用运行时每 5 秒检查原表修改时间，保存后的变化会被重新读取，再请求系统刷新小组件。关闭窗口后应用仍在菜单栏运行；从菜单栏或应用菜单退出后，新修改不会继续同步。组件保留上次成功读取的数据，并通过时间线切换到新的一天。系统控制最终刷新时间，不能保证即时更新。

桌面上右键 → **编辑小组件** → 搜索 **TodaySchedule**，选择其中的“今日事项”。Xcode 版使用 App Intent 在组件中勾选。

当前实现是视觉日程提醒，没有通知弹窗、定时铃声、开机自动启动或云端同步。

## Excel 打开时实时同步（1.3，构建 4）

Excel 已打开当前日程表时，应用通过 Excel 自动化接口直接设置删除线，然后让 Excel **保存整份日程表**。这也会保存该表其他尚未保存的修改（按用户选择启用）。无需退出 Excel；不会直接替换正在打开的磁盘文件。

- 首次使用时，在系统提示中允许“今日事项”控制 Microsoft Excel。若拒绝，可到“系统设置 → 隐私与安全性 → 自动化”更改。
- 主应用内勾选后立即请求同步；桌面组件的操作由后台应用每 5 秒读取。系统调度和 Excel 响应可能产生延迟。
- 按完整文件路径定位工作簿，并核对工作表、日期行和事项文字，不依赖当前选中单元格或同名文件。
- 如果正在编辑单元格、存在阻塞对话框、工作簿为只读、单条事项超过 512 个 Excel 字符或通信超时，保留操作并重试；不会把失败当成已同步。
- 取消勾选会恢复原先的逐字删除线状态；旧版完成标记可迁移。Excel 关闭后继续使用原有的文件写回方式。
- Excel 在运行但没有打开当前日程表时，提示打开这份表格以实时同步。WPS、Numbers、LibreOffice 仍使用保守的暂缓策略。
- 实时写入前备份的是磁盘上**上次已保存版本**，不包含当时尚未保存的 Excel 编辑。备份入口仍为“查看备份”。

## 完成标记写回 Excel

在应用里点击“启用 Excel 写回…”或“选择 Excel…”，重新选择原表，即可取得该文件的读写授权。旧版只读授权不会自动升级。主应用和桌面组件的勾选都会进入持久队列；后台应用每 5 秒处理待写回操作。关闭主窗口不影响同步，完全退出应用后则等待下次启动。首次为同一原表启用时，也会同步当前仍能匹配到的已完成事项。

- 勾选完成：给事项所在单元格的文字添加删除线。单独放在旁边的时间格保持原样。
- 取消勾选：恢复该单元格原先的样式和富文本，保留本来就存在的删除线。
- 这是从应用到 Excel 的完成标记同步；在 Excel 中手动划线暂不会反向勾选组件。
- Excel 打开当前日程表时走实时通道；Excel 未运行时直接修改文件。WPS、Numbers 或 LibreOffice 运行时仍暂缓文件写回，状态区提示退出后重试。
- 写入前重新读取并核对日期、单元格和原始文字，保留公式缓存、其他单元格和未修改的压缩包条目；写入前生成完整备份，通过临时文件原子替换，并保存中断恢复日志。
- 每次实际写入的备份都保存在本机应用共享空间；点击“查看备份”可打开。备份不会自动删除。
- 若事项移动、改名，或其他应用调整了已标记单元格的样式，程序会保留待同步操作并显示原因，不会强行覆盖。恢复对应内容后可重试。
- 当前支持具有标准样式定义、未加密且不受工作表保护的 `.xlsx`，文件上限 64 MB。保留字体、颜色、填充、边框、对齐和原有富文本；不执行公式或宏；实时通道由 Excel 自身保存，Excel 可能按其设置执行正常重算或保存事件。

## 事项末尾的提示时间

在事项后写 24 小时时间即可，例如 `示例任务A 21:00`、`读书 9:05` 或 `复习 21：00`。推荐在事项与时间之间留一个空格；也支持 `示例任务A21:00`。时间必须在文字末尾，分钟为两位，小时为 0—23。没有时间或时间格式无效时，整段文字按普通事项显示。

也支持同一行紧邻的两格：前一格写 `示例任务A`，右边一格以文本写 `21:00`。时间格会归入前一项，不再单独显示成事项；中间不能隔空格子。只含时间且没有紧邻事项的格子保持原样。Excel 若把单独时间自动转成数值，请先把该格设为“文本”再输入。添加或修改相邻时间不会重置原事项的勾选状态。

组件将名称与时间分开显示；到当天对应时间后，未完成事项显示橙色“到时间”，并优先展示。提示保留到该事项完成或当天结束。勾选完成后保留时间、取消突出显示。应用内的预览和日期列表也显示此提示。

提示日期来自事项所在的月份表和日期行，时区使用 Mac 的本地时区。通过 WidgetKit 时间线安排提示时点和午夜切换，不发通知、不响铃、不弹窗。macOS 仍可能延迟刷新，因此它不作为精确闹钟使用。先在 Excel 保存，再由后台应用同步；已经同步的提示不要求主应用一直打开。

## 原表格式

- 工作表名为 `1`—`12` 或 `1月`—`12月`。
- A 列为 1—31 的日号；B 列起每个非空单元格是一条事项，紧邻事项右侧的纯文本时间格作为该事项的提示时间。
- 当前预设学期起点为 **2026 年 10 月**，10—12 月归 2026 年，1—9 月归 2027 年。可在应用中调整。
- 空白月份表会跳过；存在日号但无事项的行显示“今天没有安排”；没有该日期行时显示“原表还没有这一天”。
- 支持 `.xlsx` 的共享字符串、内联字符串、富文本的文字内容和已保存公式缓存值。不运行宏或表格内的任何指令，不执行公式计算。
- 不支持加密文件、`.xls`、合并单元格日程、完整 Excel 日期序列号或非月份名称的工作表。当前按上述月份表格式读取，每个内部 XML 文件读取上限 16 MB。
- 完成状态绑定日期、单元格位置和文字内容；移动或更改事项文字会被视为新事项。

## 通过 Xcode 运行原生小组件

1. 从 Apple 安装完整 Xcode，完成首次启动设置。
2. 打开 `TodaySchedule.xcodeproj`，选择 `TodaySchedule` scheme 和 `My Mac`。
3. 在 `TodaySchedule` 与 `TodayScheduleWidget` 两个 target 的 **Signing & Capabilities** 中选择同一个开发团队。账号必须具备所需 App Groups 能力。
4. 两个 target 均启用 App Sandbox 和相同 App Group。公开源码使用示例标识；发布前请将 Bundle Identifier 和 App Group 中的 `com.example` 替换为自己的反向域名。App Group 预设为 `$(TeamIdentifierPrefix)com.example.TodaySchedule`；实际应展开为 `你的团队ID.com.example.TodaySchedule`。如更换标识，同时修改两个 entitlements 和两个 Info.plist 的 `ScheduleAppGroup`，保证完全一致。macOS 15 以后，团队签名与 App Group 标识必须匹配。
5. 运行应用。点击“选择 Excel…”授权读取并写回原表。正式版通过 App Group 保存快照，扩展无需直接访问桌面文件。
6. 在桌面右键 → 编辑小组件 → TodaySchedule → 今日事项，添加需要的尺寸。测试显示、勾选、取消勾选，以及保存 Excel 后的更新。

Xcode 会处理 App Intents 元数据。本机的命令行开发工具没有对应处理器，因此本机脚本构建禁用组件内的 App Intent 按钮，避免提供未经处理的交互入口。

## 开发和验证

```sh
bash scripts/test.sh
```

真实 Excel 联调（可选，需安装并允许控制 Microsoft Excel；只打开生成的临时测试工作簿，不修改日程表）：

```sh
bash scripts/test-live-excel.sh
```

新增 `CompletionStrikeStore` 保存跨模式的逐字删除线恢复信息，`ExcelLiveWriter` 通过 NSAppleScript 控制指定工作簿。应用仅对 Microsoft Excel 声明 Apple Events 沙箱例外，组件不取得这项权限。

构建无需下载第三方库。原生 SwiftUI + WidgetKit + AppIntents，Excel 使用 Foundation XMLParser 和系统 unzip 读取，使用 XMLDocument 与系统 zip 定点更新样式和事项单元格。最低 macOS 14。

测试覆盖：生成的示例表读取、工作表关系定位、共享/内联/富文本字符串、同名事项、空白日期、跨年、闰日、损坏文件、快照保存、完成状态保存与撤销。`Tests/Fixtures.py` 只生成测试数据，不改动原表。自动化测试只读取生成的测试表，不访问个人日程。写回测试全部使用生成的测试表，覆盖完整备份、原样撤销、共享富文本隔离、公式和其他文件条目保留、重复重试、并发改动检测、编辑器运行时暂缓、来源隔离、队列确认及保存中断恢复。命令行测试跳过 NSFileCoordinator 包装；签名应用始终使用文件协调。

`scripts/build-local.sh` 仅供早期本机开发参考，使用项目内 `.local-data/` 存储和临时签名；桌面组件请通过 Xcode 构建运行。不要同时运行不同构建方式生成的同标识应用。

`scripts/configure.py` 可重新生成配置和工程；手工修改 Xcode 签名设置后不要再次运行它，以免覆盖修改。

## 文件

- `Sources/App/`：文件选择、Excel 读取、自动同步、主窗口与菜单栏。
- `Sources/Shared/`：日期与事项模型、存储、卡片界面。
- `Sources/Widget/`：WidgetKit 时间线与完成状态交互。
- `Config/`：正式签名版配置。
- `Tests/`：读取与存储测试。
- 当前运行应用由 Xcode 在 DerivedData 中构建，内部包含 `.appex` 扩展。
